# Generated per-PDF findings

Each `ontology/<PDF stem>/` folder holds extracted candidates, source evidence
and decisions, document summaries, graphs, logs, revisions and evaluation samples.
Current external findings are stored globally by neighboring pair, so the same
pair can retain claims from more than one source document.
Generated findings remain ignored by Git. Preserve human-labelled evaluation
fields and historical run provenance. Do not put application source or original
PDFs here; original PDFs belong in `pdf/`.

## Current data locations

| Location | Purpose |
| --- | --- |
| `<PDF stem>/candidates.jsonl` | Original claim fields, literal PDF provenance and source decisions |
| `<PDF stem>/extraction_contexts.jsonl`, `extraction_packets.jsonl` | Original reading contexts, target ownership and extraction coverage |
| `<PDF stem>/pipeline_checkpoint.json` | Extraction compatibility: PDF hash, candidate identities and original settings |
| `<PDF stem>/source_validation.jsonl`, `source_review_history.jsonl` | Model source/scope assessments and manual review history when present |
| `<PDF stem>/summary.json`, `run_state.json`, `jobs/` | Document summary, saved execution state and archived jobs |
| `<PDF stem>/run_log.jsonl`, `llm_requests.jsonl`, `model_responses/` | Research activity, request metrics and raw final-response/recovery artifacts |
| `<PDF stem>/source_graph.json`, `audit_graph.json` | Source-supported and audit graph layers; source support is not external confirmation |
| `<PDF stem>/neighbor_evaluation_sample.jsonl`, `pathway_coverage.json` | Pair annotation sample and selected/deferred assessment coverage |
| `.provisional_pathways/` | Complete candidate identity snapshot, graph and resumable assembly checkpoints |
| `.neighbor_validation/` | Pair results, paper/query/retrieval checkpoints, histories and current supported projection |
| `.evidence_index/evidence.sqlite3` | Bounded shared parsed material, embeddings, ranking scores and compatible paper findings |
| `.historical_runs/` | Earlier document outputs retained when a run is replaced |
| `.pathway_validation/`, `.pathways/` | Historical whole-route or validated-first assembly artifacts |

Some files appear only after their stage has run. Historical `validation_runs.jsonl`
and trust ledgers are readable but are not generated by the current local-pair flow.
The extraction schema is `external-validation-v36`; current external findings use
`qualified-local-evidence-v4`. Assembly version 2 and source policy v5 version
their own decisions. Versions serve different compatibility purposes.

## Reuse, regeneration and publication

Continue reuses compatible saved work. Redo external validation starts fresh
external assessment checkpoints while preserving extraction and compatible
source/manual decisions. Rebuilding assembly does not itself grant support or
rewrite original source records. Changed inputs invalidate affected results.

The evidence index is a rebuildable performance cache, not the authoritative
research record. Removing it loses reuse and can require fetching/inference
again. Removing extraction/source checkpoints can require re-extraction or
source assessment. Do not delete artifacts during an active run.

`archive/backup/` holds separate local run copies when retained.
`deploy/render/snapshot/` is a separately exported public-viewer copy; changing
local results does not update it or an already deployed service. See
[the publication guide](../docs/deployment/render_viewer.md).
